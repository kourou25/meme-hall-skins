# 尽欢社区装扮

这是尽欢网站气泡、徽章、称号和回应框设计的独立投稿仓库。试运行期间，用户可以复制示例、设计自己的套装并提交合并请求。提交时说明作者、名称、使用到的素材及授权情况；不需要填写复杂的审核表。

## 快速预览

安装 Node.js 后，在本仓库运行 `node serve.mjs`，打开 `http://127.0.0.1:4175/` 查看现有角色、预设、官方和个人专属气泡，可搜索、选择等级、切换明暗主题。预览不连接生产账号或数据库；投稿请使用下方的受控素材格式。

也可在网站群聊点击“装扮预览”，选择本地的气泡、称号、徽章或回应框图片，并按需选择投稿的 `manifest.json` 查看切片效果。预览仅在当前浏览器显示，不会上传、发消息或改变已佩戴装扮；正式投稿仍需提交合并请求。

`public/` 保存站内现有气泡的前端样式、运行代码、注册目录和相关素材；`asset-manifest.json` 记录快照文件及 SHA-256。兼容样式 `style.css`、`chat.css` 也包含站点通用展示规则，不包含站点服务端、账户、数据库或部署凭据。`examples/simple/` 仍提供四项装扮的最简独立起点。

## 投稿

1. 创建 `submissions/<套装编号>/manifest.json` 与 `assets/` 目录。编号使用 3–48 个小写字母、数字或连字符，首字符为字母或数字。
2. 气泡、称号、徽章、回应框的图片分别命名为 `bubble.png`、`title.png`、`badge.png`、`reply.png`，也可使用 `.jpg`、`.webp`。只接受静态图片；单张不超过 4 MiB、套装不超过 8 MiB，尺寸不超过 2048×2048。
3. 提交合并请求；配置中的 `github` 须与投稿账号一致，更新现有套装须由原作者提交。检查通过后自动合并，网站同步确认后上线。

```json
{
  "schemaVersion": 1,
  "id": "morning-light",
  "name": "晨光",
  "author": "作者显示名",
  "github": "your-github-name",
  "license": "素材授权说明",
  "permission": true,
  "components": {
    "bubble": { "file": "assets/bubble.png", "slice": [8, 8, 8, 8] },
    "badge": { "file": "assets/badge.png" }
  }
}
```

`permission: true` 表示投稿人确认拥有使用和再发布素材的权限。边框 `slice` 按上、右、下、左填写像素，每项 0–64，不能超过图片尺寸；徽章无需切片。投稿不能包含 JavaScript、CSS、HTML、SVG、外链或其他可执行内容。已有站内装扮与个人权益不会因投稿改变。

不要提交账号、密钥或私密数据。不要通过装扮遮挡其他人的内容、篡改网站操作或执行不相关脚本。投稿者须确保拥有素材的使用和再发布权限。站点与个人已拥有的装扮记录以主站现有逻辑为准。

## 自动检查与状态

可信检查程序校验配置、图片内容、作者及路径。检查通过后自动合并并生成版本化目录；网站按目录同步素材并确认版本。短暂的合并或发布错误会有限重试，已合并但未生成目录的受控投稿会由定时检查恢复发布；已有运行中的任务不会重复派发。检查、合并或上线失败及等待过久会创建 Issue，站长也可在网站系统通知中查看。定时检查约每 15 分钟运行一次，实际时间受 GitHub 和网站调度影响。检查通过不代表网站已经更新。

机器检查无法确认素材授权声明是否属实；站长可处理争议并撤回作品。监控自身无法运行时，Issue 提醒也可能无法送达，应通过 Actions 页面检查运行状态。

仓库代码使用 MIT 许可。图片、角色及其他设计素材由各自作者在套装目录中注明授权，代码许可不会自动授予素材使用权限。
